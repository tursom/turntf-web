# 界面与交互优化验收

## 范围

本次仅调整 turntf-web 的界面与客户端交互，不修改服务端协议及 SDK。保留 React、Ant Design 和现有权限模型。

- 主导航：桌面固定侧栏，窄屏抽屉；用户详情与消息列表高亮用户管理栏目。
- 聊天：会话状态隔离、历史加载失败重试、会话草稿、发送状态与受控自动滚动；手机端单栏切换。
- 管理页面：错误与旧数据提示、刷新、成功更新时间、局部表格横向滚动。
- 用户与事件筛选：仅筛选当前已加载的数据，不代表服务端全量检索。
- 表单：提交中反馈与重复提交保护；失败保留输入。

## 自动检查

在模块根目录执行：

```sh
npm test -- --run
npm run build
git diff --check
```

## 聊天浏览器回归

先启动 Vite，再使用已安装的 Playwright 与 Chromium 执行：

```sh
CHAT_TEST_URL=http://127.0.0.1:5175 \
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs \
CHROMIUM_PATH=/path/to/chromium \
node src/components/chat/chat.browser.mjs
```

若项目环境能直接解析 `playwright`，可省略 `PLAYWRIGHT_MODULE`；使用 Playwright 默认浏览器时可省略 `CHROMIUM_PATH`。脚本模拟认证、网络和会话列表，验证真实聊天组件在 1440px、390px、320px 下的会话隔离、草稿、历史重试、滚动及发送失败反馈，不访问真实业务接口。

## 浏览器验收

使用测试环境或拦截的模拟接口，不对生产账号执行删除、修改密码或发消息操作。

1. 在 320px、390px、1440px 宽度检查登录、用户、事件、集群和聊天页面。整页不得横向溢出；宽表格在自身容器内滚动。
2. 手机打开主导航，进入目标页面后抽屉关闭。直接打开用户详情和用户消息列表时，用户管理栏目保持选中。
3. 给历史请求增加延迟，从 A 会话切换至 B；A 的结果只能写入 A。发送中切换会话也不能把结果或错误写入 B。
4. 分别编辑 A、B 草稿并往返切换；发送成功仅清除对应草稿，失败保留输入。
5. 阅读较早消息时收到新消息，应保持阅读位置；新消息按钮可回到底部。接近底部或主动发送时自动跟随。
6. 分别模拟首次请求失败、空结果、刷新失败。失败不能显示为真实的零值或空列表；刷新失败时保留旧数据并提示。
7. 搜索或修改筛选条件后，检查分页回到有效页；清空筛选恢复已加载列表。
8. 点击集群节点的“查看在线用户”，应切换标签并选择该节点。
9. 延迟登录、修改密码、编辑用户请求，连续点击确认只产生一个提交；失败后按钮恢复且输入保留。
10. 联系人订阅状态尚未加载或加载失败时，不应显示可操作的错误订阅状态；请求中禁止重复操作。

## 限制

草稿仅保存在当前聊天工作区的内存中；离开聊天页面、刷新或退出登录后不保留。指标页保留 Prometheus 原始文本，不引入自定义图表或解析器。
